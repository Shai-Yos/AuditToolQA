================================================================================
                    AUDIT MANAGEMENT TOOL — PROJECT STRUCTURE
================================================================================

Tech Stack: Next.js App Router · TypeScript · Tailwind CSS · Prisma · SQL Server
Auth:        Email-based session cookie (`audit_user_email`) with DB-managed roles
API Layer:   tRPC + traditional Next.js API routes & Server Actions
Package Mgr: pnpm

================================================================================
  DATA FLOW: Request Lifecycle
================================================================================

  1. Admin creates Audit          → Audit record in DB
  2. Admin assigns Users          → AuditAssignee records
  3. User sees assigned Audit     → Filtered by AuditAssignee
  4. User creates Request         → Request record linked to Audit
  5. Users upload Documents       → Document records + files in /public/uploads/
  6. Team discusses in Chat       → ChatMessage records per channel
  7. Admin transcribes meetings   → ChatMessage in *-transcription channel
  8. Requests move through board  → Status updates (Kanban)
  9. All actions logged           → ActivityLog records
  10. Cron auto-completes audits  → Status → COMPLETED when all done


================================================================================
  CHANNEL NAMING CONVENTION (Chat)
================================================================================

  Each audit has front rooms (FR1, FR2, ...) and each room gets two channels:

  fr{n}-comm             Communication channel (team chat)
  fr{n}-transcription    Meeting transcription (admin edits, users read-only)

  Example for an audit with 2 front rooms:
    fr1-comm, fr1-transcription, fr2-comm, fr2-transcription
